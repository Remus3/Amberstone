**NO AI OR BOT ATTRIBUTION (kit v13, MAIN 2026-10-08 2246 section 1, FLEET-COMMON item 17).** Tracked `.githooks/commit-msg` runs `python "ops/fleet_kit/fleet_identity.py" commit-msg "$1" || true` after RC's own Co-Authored-By strip (it strips every AI / bot trailer, any `Claude-*:` line and a claude.ai session URL line, never rejects); `.githooks/pre-push` runs `printf '%s\n' "$REFS" | python "ops/fleet_kit/fleet_identity.py" pre-push "$@" || exit 1` FIRST, before the sibling sweep, the credential scan and LFS. ## BOT-PR MERGE RULE (MAIN ORDER 2026-10-19-0034, FLEET-COMMON item 17)

**BOT-PR MERGE RULE (MAIN ORDER 2026-10-19-0034 DEPENDABOT-MERGE-RULE, FLEET-COMMON item 17).** Contributors show ONLY the operator: every default-branch commit has the operator as author AND committer and carries no `Co-authored-by:` line of any kind. A Dependabot or other bot PR is never merged as-is (no merge commit, no rebase-merge). MAIN allows path A (GitHub squash, operator author, trailer removed) or B (re-apply the bump as an operator commit); RC takes B ONLY, because any merge done on GitHub writes GitHub's web-merge committer (kit-v14 ORDER section 4; guard `tests/test_no_bot_push_or_ui_merge.py`). Recipe: `git cherry-pick --no-commit` of the PR head (a plain cherry-pick keeps the bot author and skips the commit-msg hook), regenerate any hashed lock locally, commit through fleet_gitlock with an operator-written message, push; the PR closes itself, and a manual close is a remote act. Decline = widen the `.github/dependabot.yml` ignore. Read-back after every bot-PR landing and at /done after the push: `python tools/bot_merge_check.py` (exit 1 = a non-operator / bot / web-merge identity or any co-author line reached the default branch; fix only with `fleet_rewrite.py` under MAIN 2312's scope, at the halt boundary) and `gh api repos/<owner>/<repo>/contributors`. Repo auto-merge stays off; Dependabot alerts stay on. Long form `docs/OPERATIONS.md`; guard `tests/test_bot_merge_check.py`.
