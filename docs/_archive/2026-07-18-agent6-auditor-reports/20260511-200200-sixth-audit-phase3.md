## New findings (this pass)

### MEDIUM

**M-01 - HTTP `?bbox=` override on `/api/minimap-crop` skips the bounds-validity check that `agents/_minimap_bbox.py` enforces for persisted entries**
- **File:line:** `agents/supervisor.py:596-605`. Compare to the persisted-entry
  validation at `agents/_minimap_bbox.py:66-68`:
  ```python
  if r <= l or b <= t:
      _log.warning("bad %s bbox (r<=l or b<=t): %r", key, raw)
      return None
  ```
- **What's wrong:** The HTTP override path parses `?bbox=x1,y1,x2,y2` and
  validates only (a) parseable as ints and (b) exactly 4 elements. It does
  **not** check `r > l` and `b > t`. The persisted-calibration path does.
  Inconsistent contracts on the same `bbox` tuple flowing into
  `PIL.Image.crop()`.
- **Why it matters:** PIL's `Image.crop()` is permissive - it accepts
  degenerate boxes (`(50, 50, 50, 100)` → 0×50 image) and inverted boxes
  silently rather than raising. The caller therefore receives a HTTP 200 OK
  with a malformed/empty PNG; the dashboard overlay renders empty without any
  signal to the operator. Worse: out-of-range coordinates
  (`?bbox=-1000000,-1000000,2000000,2000000`) silently clip to full-frame,
  defeating the intent of an override entirely. The threat surface is small
  (the supervisor's `:8890` HTTP server is dashboard-internal, not exposed
  beyond the Tailnet), but it's a real defense-in-depth gap and a real
  inconsistency vs. the persisted-entry path.
- **Concrete fix:** Add the same validity check to the HTTP path:
  ```python
  if bbox_raw:
      try:
          parts = [int(x) for x in bbox_raw.split(",")]
          if len(parts) != 4:
              raise ValueError
          l, t, r, b = parts
          if r <= l or b <= t:
              raise ValueError("r<=l or b<=t")
          # Optional: clamp coords to a sane range, e.g. 0..10000
          if not all(0 <= c <= 10000 for c in parts):
              raise ValueError("coord out of range")
          bbox = (l, t, r, b)
      except ValueError as ve:
          self._send_json(400, {"error": f"bbox must be x1,y1,x2,y2 with r>l,b>t: {ve}"})
          return
  ```
- **Action:** Proposal `P-audit6-m01-bbox-override-validate` filed for
  Agent 2. Bundles trivially with a 2-line test added to
  `tests/fu01_minimap/`.

**L-02 - `core/decision_detector.py:467` jungle-zone docstring is SR-specific but reads as mode-general**
- **File:line:** `core/decision_detector.py:467-476` -
  `_is_enemy_jungle_zone()` docstring says "Order/CHAOS naming maps to
  blue_/red_". True on SR; ARAM has no jungle, Arena/Brawl have
  unrelated layouts. The function is gated upstream to SR-only callers,
  but the comment leaves that gate implicit.
- **Why it matters:** Cosmetic; will not change behavior. But ADR-007 is
  being actively iterated on, and a future maintainer extending the
  detector to ARAM "double-jungle" zones (unlikely but plausible) would
  read the docstring as authoritative.
- **Concrete fix:** Prepend one line to the docstring: `"""SR only.
  Order team's jungle is blue_*; CHAOS is red_*. Callers gate on
  mode."""`.
- **Action:** Logged as INFO/LOW; no proposal filed unless ADR-007
  shipper wants it. Cheap to fold into the next ADR-007 commit.

**L-03 - `tools/gamepc_keybind_listener.py:103-115` retry path has no operator-visible diagnostics**
- **File:line:** `tools/gamepc_keybind_listener.py:103-115`. Network
  failures (timeout, 5xx) are logged at WARNING but the per-key retry
  counter is not exposed.
- **Why it matters:** Charter §7 "log entries that could leak the
  Anthropic API key" - this listener does **not** leak; verified clean.
  But during gameplay, a flapping network silences the listener and the
  operator only sees "nothing happened on hotkey press." Diagnosis is
  hard without a counter or recent-error surface.
- **Concrete fix:** Track per-key retry attempts in a small dict; emit
  `WARNING attempt %d/%d` on each failure. Optional: expose via a
  `/api/keybind-listener/status` route on Game-PC.
- **Action:** Logged as LOW; no proposal filed unless ADR-007 shipper
  wants it. ADR-007 is in-flight, so leaving as INFO until that work
  reaches "feature complete."
