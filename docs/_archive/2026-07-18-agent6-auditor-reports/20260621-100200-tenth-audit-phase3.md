### HIGH

**H-04 - publisher freshness vs watcher freshness conflated in alarm path**

- **Location:** `dashboard/routes_state.py:316-323` (rollup) +
  `dashboard/routes_health_peer.py:121-127`.
- **What:** `age_s` is computed as `time.time() - rec.received_at`, i.e.
  the time since the publisher last POSTed. The publisher itself,
  however, sends a snapshot of the local watcher heartbeat
  (`heartbeat.updated_at`), and the rollup never compares that field
  against `now()`.
- **Live evidence:**
  - Peer `peers.peer.age_s = 0.2s` (status green)
  - But `heartbeat.updated_at = 1780344276` = 2026-06-01, **19.6 days
    stale**.
  - Same `pid=7976` carried since 2026-05-29 - either the watcher is
    wedged (alive flag still True, no fresh polls) or the publisher is
    serializing a frozen snapshot. Either way the alarm shows green.
- **Why it's wrong:** A frozen Peer watcher will keep the dashboard
  green indefinitely because the publisher relays a stale heartbeat
  every 60s. This is exactly the false-confidence failure mode H-01 was
  supposed to close.
- **Concrete fix:** in `routes_state.py` rollup, compute a second
  `heartbeat_age_s = now - heartbeat.updated_at` and pass it through
  `_peer_health_status()` alongside the publisher age. Status should be
  `max(publisher_status, watcher_status)`. Or: simply replace `age_s`
  with `max(now-received_at, now-heartbeat.updated_at)`.
- **Disposition:** Proposal filed for Agent 2.
  `agents/agent6_auditor/proposals/20260621-100200-h04-watcher-freshness/`.
