# Real-time CV stack for a live League client - assembled answer, 2026-07-28

Answers `research ocr cv.txt` (RM-121 item 2). Five parallel research slices,
each scoped off RC's actual baseline rather than a blank sheet, then adjudicated
against disk. Slice reports with every citation and every UNVERIFIED item:
`docs/_archive/2026-07-28-cv-stack/`.

**Read this first.** The question was "which technology do I download and
assemble". The honest answer is **much less than the brief assumed**, and the
reason is not pessimism - it is that four of the seven targets are already
solved, banned, or free. What survives is small, classical, and cheap.

---

## The five findings that change the plan

### 1. The runtime layer contributes almost none of the 2 s -> 100 ms step change

RC runs **ZERO local neural inference today**. The 2-second cadence is the poll
interval, plus the JPEG/base64/HTTP hop, plus a cloud Sonnet call. **Tensor math
is currently 0 ms.** The measured spread between GPU execution providers is
under 2x (nietras, RTX 3070, ResNet152: TensorRT 5.80 ms / DirectML 7.80 ms /
CUDA 9.05 ms / CPU 37.47 ms) - smaller than the architectural changes that
deliver the 20x. Choosing a runtime is not the lever; removing the hop is.

Corollary the brief got backwards: **detectors do not run "at 1080p/1440p"**.
They run at 640, or on crops. Resolution affects capture and resize (1.78x more
bytes at 1440p), not convolution cost. Crop first and the question evaporates.

### 2. Enemy cooldowns - the brief's priority-4 target - are a DO-NOT-BUILD

Not a hard problem: a forbidden one. League **renders no enemy cooldowns
anywhere**, and Riot's third-party policy explicitly forbids "tracking of enemy
summoner spells cooldowns", ability cooldowns and ultimate timers. The only
route is a memory read, which is **Vanguard-banned AND policy-banned**. Recall
detection has no numeral either (recall is a bar; the clock is `:2999`).

**UNVERIFIED:** Riot's own policy URL returned 403; the prohibition text was
read via Overlay Platform M's compliance page. Confirm before quoting it as Riot's words.

The one legitimate OCR target left standing is **objective spawn timers** -
genuinely rendered, and `:2999` exposes no objective timer field.

### 3. RC's OCR tier is aimed at the wrong things - verified on disk, not reported

`data/vision_regions.json` holds 21 regions. **Eight are exact `:2999`
duplicates** (`gold`, `cs`, `kda`, `level`, `ally_levels`, `timer`, `hp`,
`mana`), and **zero `*_cd` regions exist**, which makes `_ocr_cooldown()`
(`core/vision_tesseract.py:490`) dead code no region can reach. So the OCR tier
spends 100 pct of its budget on fields the API serves exactly and free, and 0
pct on the one real gap. `configure_drop_fields()` (`:536`) is already the
mechanism. **The cheapest win in this report is deleting work, not optimising
it** - about 1.4 s per pass.

The ally HP/mana/ult regions are genuine gaps and correctly use pixel counting
rather than OCR. Leave them alone.

### 4. Classical beats neural on nearly every remaining target

Measured on Legion, not cited: roster-of-10 template match on a 32x32 crop
**0.94 ms**; full 173-catalog **16.0 ms**; dhash **0.19 ms**; blob detect on a
real 416x416 corpus frame 11-19 ms; full minimap pass ~28 ms, CPU only.
**Roster-scoping is worth 17x - more than any model choice.**

And the dependency price is real: `cv2` 5.0.0 and `scipy` are present, but
**`onnxruntime` and `torch` are both ABSENT**. Any net is a 300 MB - 2.5 GB new
dependency on a box already running League + Vanguard + OBS.

### 5. Tracking is not needed, and would actively harm the product

A MOT tracker emits arbitrary relative ids ("object 7"); RC wants "that dot is
Thresh". Tracking is a workaround for being unable to classify - RC **can**
classify, cardinality is known (10) and identities are known a priori. The
correct algorithm is a **10x10 Hungarian solve** (`scipy`, already installed,
microseconds) over an event-feed-informed cost matrix, which enforces
one-champion-one-dot - a constraint the current greedy argmax violates and that
no MOT tracker can even express.

The deeper reason: coaching value lies in knowing what you do NOT know
("jungler unseen 22s"). A Kalman filter's entire job is to paper over that gap.

## Minimap identity: the promising result, with its caveat attached

Masking the known team-colour ring out of the correlation takes 27 px icons from
93.3 pct to 100 pct top-1 and **triples** the nearest-confuser margin
(0.212 -> 0.674). Real icon diameter measured off RC's own corpus frames is
**25-39 px**, not the ~27 px worst case previously assumed. The switch already
exists and is OFF: `core/vision_template_match.py:75`, `_USE_CIRCLE_MASK = False`
(verified on disk).

**Do not flip on this evidence.** Those accuracy figures are **synthetic
composites sharing a single source PNG** - they measure scale, ring and
occlusion robustness, NOT the real domain gap. `data/vision_calib_reference/`
holds 24 files to re-run against first.

This does not contradict the standing "minimap presence not identity" finding
(memory `project_zoi_minimap_reality`): that negative was about **colour
segmentation**, and its own docstring points at template matching. This is
walking through that door, not re-litigating it.

**A ceiling nothing beats:** when two champions coincide, the GAME ITSELF draws
one portrait. That is a rendering fact, not a detection failure - no CV,
classical or neural, recovers it.

## Training data: the premise corrected

The operator's claim was "free, exact, unlimited". **Masks are free per instant;
INSTANTS are not.** At T4's own measured ~10-15 s per instant, attended and
exclusive, an 8-hour session yields ~2000-2900 frames. Realistic corpus is
**10^3-10^4 frames from TENS of matches** - so correlated data is a first-order
problem from frame one, not a later scale problem, and it rules in a small model
on a frozen backbone.

**The static-scenery caveat is HALF CONFIRMED.** True for set-subtraction
classes (RC measured ~87 pct scenery). **REFUTED for a single-toggle diff** -
scenery cancels exactly, proven by RC's own 0-pixel control. Corollary worth
keeping: **a two-time diff is a CHANGE mask, not an object mask.** Never put one
in the training corpus; use it only as an offline mover discriminator.

**Auto-masks are CLASS masks, not INSTANCE masks** (toggles are per-class; RC
measured 10 blobs for 6 champions). Semantic segmentation is the right consumer;
instance segmentation is justified for champions only.

**The domain-gap trap, free to avoid:** every RC experiment so far ran
interface-off/fog-off. The INPUT must be the live-realistic render and the MASK
is `diff(that, that-minus-one-class)`. **Never train on the ablated frame** or
the model learns a renderer that does not exist at inference time.

**What auto-masks CANNOT teach:** minion type, monster vs pet vs plant, ward
type, wave push direction, warded-by-us, occlusion semantics, every event
boundary, and minimap icons (interface toggles are all-or-nothing - use template
matching).

**Free labels nobody was using:** `core/replay_seek.py:137` proves `allgamedata`
serves from the same `:2999` at the same paused instant, so the event feed gives
exactly-aligned weak temporal labels (fight windows from `ChampionKill`
clusters, objective contests, `MinionsSpawning`) plus free champion identity per
mask blob via `screenPositionBottom`.

**Cheapest win here needs no model at all:** `interface*` toggle diffs give exact
HUD element extents and **auto-calibrate `data/vision_regions.json` at any
resolution**.

**Small objects:** do NOT resize 2560x1440 to 640 - a 26 px ward becomes 6.5 px,
below stride. Tile with SAHI or keep native resolution. Never report pixel
accuracy at 0.3 pct foreground.

## Licences - the constraint that eliminates the obvious choice

**AGPL-3.0 covers YOLOv5 / v8 / v10 / v11 / v12 / v13 / YOLO26.** Section 13
triggers on **network** interaction, and **RC's primary UI is an HTTPS server on
`:8888`** - so the entire Ultralytics line is disqualified, not merely
inconvenient. Ultralytics further claim the licence propagates to trained
weights. v6/v7/v9 are GPL-3.0, still copyleft.

Clean Apache-2.0 set: **YOLOX, RTMDet, RT-DETR/v2, D-FINE, DEIM, RF-DETR
Nano..Large**. If a net is ever needed: **D-FINE-N** (Apache, 42.8 AP, claimed
2.12 ms on T4) or **RTMDet-tiny**.

Traps: **YOLO-NAS** is Apache framework with **NON-COMMERCIAL weights**;
**RF-DETR XL/2XL** is PML 1.0; **MMYOLO is GPL-3.0** while the same RTMDet-Ins
is Apache via MMDetection; and tracking via `ultralytics.track()` **imports AGPL
even though ByteTrack itself is MIT** (BoxMOT is AGPL too). The whole OpenMMLab
stack was last pushed mid-2024 and is effectively frozen.

Permissive escape for the mask lane: **segmentation_models.pytorch** (MIT,
pushed 2026-07-28) for semantic seg, **RF-DETR-Seg** (Apache-2.0, 1.8.3) for
instance seg, torchvision 0.28.0 (BSD), SAHI 0.12.2 (MIT). **SAM-family is not a
training consumer here** - we already have perfect masks.

## Capture

**Recommended: Windows.Graphics.Capture, window-directed, via `windows-capture`
2.0.0 (MIT).** It is the only one of the four candidates that can name the
League window while fullscreen, and it is occlusion-proof - so RC's own overlay
stops corrupting RC's own input.

**VANGUARD, hard flag, now confirmed three independent ways:** OBS **Game**
Capture injects `graphics-hook64.dll` into the game. Banned technique. RC's own
`docs/adr/ADR-011:43-44` already decided this; `docs/OBS_CV_MINIMAP_PLAN.md` O2
contradicted its own ADR and has been corrected this session (`063ca589`). Take
WGC directly and skip OBS for frames entirely.

Can hold 10-30 FPS: WGC, DXGI (`dxcam` 0.3.0, MIT), BitBlt of a crop only.
Cannot: full-desktop BitBlt (RC's current path), OBS `GetSourceScreenshot`,
`PrintWindow`. DXGI and WGC both hand back GPU textures; **every Python wrapper
then forces a CPU roundtrip**. DXGI cannot target a window, only a display.

**BLOCKING PREREQUISITE, measured:** `game.cfg` reads `WindowMode=2` at
2560x1440, and RC's own history records that value three incompatible ways -
Windowed (`history_notes.md:15826`), borderless (`:16484`), EXCLUSIVE fullscreen
(`:21044`). The `:21044` entry is an incident report of an always-on-top overlay
being occluded in-game, which is the strongest evidence for exclusive
fullscreen - under which Microsoft does not guarantee WGC. **Settle it at the
in-client dropdown; no amount of research closes it.** Second risk: the WGC
system yellow border is not removable on Win10 19045 (`IsBorderRequired` is
Windows 11 only).

Also confirmed on disk: `EnableReplayApi=1` is already set, so the replay-API
prerequisite for the training lane is live.

## GPU contention - the famous answers do not exist here

Hardware probed live: **RTX 5070 12 GB Blackwell, driver 610.62, Ryzen 7 7700X,
ONE display adapter** - the iGPU is BIOS-disabled, so "offload to the iGPU" is
not currently available. That also **eliminates OpenVINO outright**: its GPU
plugin is Intel-only.

- CUDA MPS: 64-bit **Linux only**.
- MIG: datacenter / RTX PRO only.
- CUDA stream priority: a hint, intra-context, and cannot see the game (League
  is a D3D client).
- D3D12 queue priority: has NORMAL / HIGH / GLOBAL_REALTIME and **no
  below-normal** - you can only go up, never yield.
- `nvidia-smi`: compute mode needs TCC (impossible on GeForce), `-pm` is Linux
  only, `-pl` throttles the game too.

**The one genuine lever found:** `D3DKMTSetProcessSchedulingPriorityClass`
(Gdi32.dll) exposes `_IDLE` / `_BELOW_NORMAL` GPU scheduling classes - the only
documented Windows API that expresses "run this process's GPU work below
normal". **Whether NVIDIA's WDDM scheduler honours it is UNMEASURED, and it is
the highest-value single experiment in this report.**

What actually works meanwhile is workload shaping: duty cycle
(`steal = kernel_ms / period_ms`), crops, INT8, one persistent context,
sleep-not-spin, and capping League's FPS. **Design target is sub-1 ms kernel,
because 144 Hz is a 6.94 ms frame budget.**

## Orchestration

- **DeepStream: closed door.** No native Windows (WSL2 Linux container only,
  with NVIDIA's own perf disclaimer), and the runtime binaries are proprietary
  despite an Apache-2.0 source repo.
- **Frigate: an MIT appliance**, Docker-first, not importable. Lift its
  motion-gate DESIGN (~50 lines of OpenCV), not its code.
- **Norfair 2.3.0 (BSD-3-Clause) is the one true LIFT** - pure Python,
  numpy/scipy/filterpy, no torch, no mandatory OpenCV, Windows-clean. Frigate
  itself pins `norfair==2.3.*`, so the motion-gate + Norfair pairing is proven,
  not theoretical. (Note this sits against finding 5: lift it only if a tracking
  need survives the Hungarian argument.)

## Ranked assembly order

Ordered by payoff per unit of effort. Each step is independently useful - none
is a prerequisite for the next except where stated.

1. **Delete the 8 duplicated OCR regions** via `configure_drop_fields()`. Frees
   ~1.4 s per pass. Zero new dependencies, negative lines of code. **Live-path
   change - own session, not a side effect of a research run.**
2. **Grab a bbox instead of the whole desktop.** Zero new dependencies, ~38x
   fewer pixels for the minimap. Pure win on the existing GDI path.
3. **Settle the Window Mode question in-client**, then prove ONE WGC frame with
   the RC overlay on top. This gates everything below it.
4. **Re-run the circle-mask identity experiment against the 24 real frames** in
   `data/vision_calib_reference/`. If it holds, flip `_USE_CIRCLE_MASK` and
   replace greedy argmax with the 10x10 Hungarian solve.
5. **Second in-process capture lane** at 10-30 FPS with no JPEG/base64/HTTP.
   Leave `:8889`'s 2 s lane alone - two cadences, two lanes; 2 s at 1280 px is
   correct for Sonnet.
6. **Objective-timer OCR** via a fixed-font numpy template matcher (0.100 ms per
   crop measured), with RapidOCR rec-only as the fallback tier. Pin the version
   - Python 3.14 silently downgrades RapidOCR to 1.2.3. **Do not adopt
   PaddleOCR** (no 3.14 support, framework dependency, vendor-reported 21 ms).
   Build the reject path on domain range + countdown monotonicity + N-of-M
   temporal agreement, NOT on engine confidence.
7. **`interface*` toggle diffs to auto-calibrate `vision_regions.json`.** No
   model, any resolution.
8. **Measure `D3DKMTSetProcessSchedulingPriorityClass`.** Cheap, and it decides
   whether any GPU work is safe to run beside the game at all.
9. **Only then, if a gap survives:** ONNX Runtime (MIT) + DirectML EP, crops,
   batch 1, fixed shapes, model resident. Chosen for operational reasons - no
   engine-build step, no per-driver rebuild, and the EP swap to ORT-TensorRT is
   one constructor argument later. **Strategic risk flagged:** ORT's own docs
   say DirectML is in "sustained engineering", with new work moved to Windows ML.

**Expected end-to-end latency** on the classical path (steps 1-7): capture crop
~1-5 ms + minimap pass ~28 ms CPU + template/OCR ~0.1-3 ms, comfortably inside
100 ms without a single neural inference. The sub-100 ms target does **not**
require the neural stack; steps 1-5 alone carry it.

## Where each option stops being good enough

- **Classical template matching** stops at anything not drawn from a fixed
  sprite set at known geometry - live wave state, minion classification, ward
  ownership.
- **The `:2999` event feed** stops where the game does not emit: no positions
  for non-self champions, no objective timers, no wave state.
- **Auto-masks** stop at game state (see "cannot teach"), and at ~2900
  frames/8 h of attended time.
- **WGC** stops if League is in exclusive fullscreen (unsettled) and at the
  Win10 yellow border.
- **DirectML** stops at "sustained engineering" - fine for a build now, a
  migration later.
- **The whole neural lane** stops being justified at all if steps 1-7 close the
  target list, which on this evidence they largely do.
