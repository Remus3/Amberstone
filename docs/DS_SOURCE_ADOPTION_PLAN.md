## Outcome of the dive

Two actionable wins and one explicit non-goal:

- **WIN 1 (high value, validated) - AA-windup offset tier.** The `wiki_stats` sidecar leaves 110
  champions on a flat 0.25s default; 109 of them carry `attack_delay_offset` from which real windup
  is recoverable. `windup_fraction = 0.300 + attack_delay_offset` is validated 4/4 EXACT against the
  wiki's own published Windup% (Caitlyn 17.708, Ashe 21.93, Vayne 17.544, Jinx 16.875). Only Alistar
  has neither field. Reproduce: `python tools/ds_windup_offset_compare.py` (171 champs, 119 changed).
- **WIN 2 (larger, separate session) - Meraki ability-ratio freshness.** Meraki `champions.json` is
  ~10 months stale (frozen 2025-08-01, patch ~25.08 vs live 16.11). The balance-sensitive blast
  radius is `champion_abilities.json` ratios + base damage, sourced live from Meraki
  `effects[].leveling[]` via `tools/daemon_slayer_abilities_extract.py`. Add a content-freshness
  guard keyed to PATCH (the `fetched_at` timestamp lies over the frozen `latest` endpoint).
- **NON-GOAL - CC-duration sourcing.** DS already owns CC durations hand-curated in
  `agents/daemon_slayer/_per_spell_cc.py` (108 entries / 89 champs) + `cc_conditional_registry.json`,
  insulated from Meraki staleness; `docs/DS_DATA_SOURCE_SWEEP_2026-05-30.md` already proved CC-seconds
  are structured on NO machine source. Do not duplicate this. Only CDragon discovery aids (cc_tags /
  missile / ammo) have residual value and are already tracked.

## Conversion rule (load-bearing)

`combo.py` consumes `attack_cast_time` as FIXED absolute seconds (no AS-derived windup curve;
docstring L32-35, loop L317-348). So store `windup_seconds = (0.300 + offset) / as_base` (base AS at
level 1). This overstates windup once AS rises but is a strict improvement over a flat 0.25 for 109
champions. If a future engine adds AS scaling, store the FRACTION and divide by current AS at runtime.
