## Ambiguities I resolved

Every resolution below is mine. None was settled by consulting any other file.

**1. The tie-breaker and 3.2's boundary contradict each other outright, and one of
them kills a value the convention defines.**

The tie-breaker: "if an existing check could not have seen this defect without
being REWRITTEN, it is `GATE-ABSENT`, not `GATE-EXISTING`. 'Rewritten' means its
predicate changed, its input corpus widened, or a new assertion added."

3.2's boundary, two paragraphs later: "if a check DID exist but was too narrow,
the value is `GATE-EXISTING` with `prevention_why: WRONG-SCOPE`, not
`GATE-ABSENT`."

A too-narrow check is by definition one whose corpus must be widened. Read
together, `WRONG-SCOPE` can never be assigned, yet 3.1 lists it as one of exactly
three permitted reasons. **My resolution:** the tie-breaker is honoured as
written, since it is the clause declared to apply FIRST, so `WRONG-SCOPE` cases go
to `GATE-ABSENT`; `GATE-EXISTING` survives only for `WRONG-TIME` and `VACUOUS`,
which the "rewritten" test does not touch. This is the single largest lever in my
block - it moved chunk1-18, chunk1-55 and chunk2-03. RC did not relocate this gap,
it created it: LW's instrument at least did not contradict itself on a value it
had not defined.

**2. The `prevention_why` field 3.1 makes mandatory has nowhere to go.**

3.1: "Record the reason in `prevention_why` as exactly one of `WRONG-SCOPE`,
`WRONG-TIME`, or `VACUOUS`." The required output schema has four keys and
`prevention_why` is not among them. I put it in `note` on chunk1-07 and chunk1-15.
A convention that mandates a field its own pass cannot emit is underspecified at
the point of use.

**3. Where a session's own act stops being a "standing check". This is RC's
relocated gap, not a closed one.**

3.4 defines a standing check as "a NAMED instrument WITH A FIRING VERB which a
STANDING RULE REQUIRED to run", explicitly admitting "a mandated self-audit", and
then excludes "An unprompted re-read". RC's tree mandates re-verification before
any assertion, so on RC's own rows nearly every self-check is simultaneously a
mandated self-audit and an unprompted re-read. **My resolution:** I required a
NAMED CONTROL - a gate, verifier, adjudicator, adversarial pass, suite, hook or
dry cycle - and refused the value to bare acts of measuring, re-deriving,
re-probing or re-reading, however mandated. That line is mine; the convention does
not contain it. It decided chunk1-01, chunk1-38, chunk1-39, chunk1-46 and
chunk1-57 against `GATE-FIRED-CAUGHT`, and chunk1-56 for it purely because the
row called the instrument a dry cycle. RC diagnosed LW for delegating the eight
definitions to another document; RC defined all eight and left the predicate that
selects among them - "what counts as an instrument" - exactly as manufacturable.

**4. Whether `GATE-FIRED-CAUGHT` and `GATE-ABSENT` may co-apply.**

3.2 requires that "No mechanised instrument in this tree graded the property AT
THE MOMENT THE DEFECT WAS WRITTEN". Read literally, that is true of almost every
row, because gates fire after the writing, so `GATE-ABSENT` would co-apply to
nearly every `GATE-FIRED-CAUGHT` row and the set would stop discriminating.
**My resolution:** I admitted `GATE-ABSENT` alongside `GATE-FIRED-CAUGHT` only
where the ROW'S OWN TEXT independently states a gap ("invisible to CI", "no guard
on it", "pinned only INDIRECTLY", "before any gate could see them"), leaning on
3.9's admission rule. Four rows took both. A different reader applying 3.2
literally would double that count, and nothing in the convention stops them.

**5. `origin_time` sub-values are mandated singular and the corpus is not.**

Section 5: "A sub-value is REQUIRED on `INHERITED`, exactly one of". chunk1-48 is
two-thirds `DECAYED` and one-third `BORN-WRONG` by the row's own arithmetic. I
took the majority. The convention offers no mixed-row rule and forbids a set here
while permitting one for `prevention`, with no stated reason for the asymmetry.

**6. `INHERITED` for a claim carried by CODE rather than by a note.**

5.1 keys on whether the claim was "already committed, filed, or sitting in a
tracked artifact". A wrong assumption baked into shipped code is committed, but it
is not a RECORD anyone wrote down as a claim. **My resolution:** committed code
counts, so chunk1-35, chunk1-36, chunk1-41, chunk1-49, chunk1-56 and chunk1-60 are
`INHERITED`. Under the narrower reading all six flip to `FRESH`, which is a large
swing in a field whose headline is an inherited share.

**7. `fix_chain` when the remedy is invalidated by later work rather than by
being wrong.**

Section 6 counts "the number of times THE REMEDY FOR THIS EVENT'S DEFECT was
itself subsequently refuted". chunk1-27's THREE became FOUR by refutation and then
SIX because a closing arm added call sites; chunk1-40's needle "broke TWICE". I
counted one link in each, but section 6's `chain_kind` list contains no value for
"the remedy stopped being true because the tree moved", and 6.1's floor rule
argues for scoring both DOWN to 0. I am not confident in either row.

**8. The 3.8 shape test against causal and characterisation errors.**

3.8 routes "a count, a path, a line range, a SHA, the presence or absence of a
symbol, a file's existence, a field's value" to `GATE-ABSENT`, and reserves
`ADVERSARY` for "a reasoning error, a mischaracterisation, an unsupported
generalisation, or a wrong inference from correct facts". A misattributed CAUSE
(chunk1-54) and a mechanism mischaracterisation (chunk1-21) sit in both lists at
once: each is settled by a discrete measurement, and each is an inference error.
I took `ADVERSARY` in both on the ground that the FILED claim was an inference. A
reader applying "the SHAPE of what was wrong" to the underlying datum instead
lands on `GATE-ABSENT`, and the row's text supports them equally. This is the
same IN/OUT family boundary 3.5 was written to protect, crossed by a different
door.

**9. `PROXY-MEASURE` condition 2 when the computation itself mismatched its
inputs.**

3.5 requires that the instrument "was not wrong about the thing it measured".
chunk1-20 divided an ANSWERED count by an ARRIVAL span - each input correct, the
quotient meaningless. That is neither a correct answer to another question nor a
wrong measurement. I admitted it, because the row names the substituted pair,
which is the checkable half of 3.5. The clause does not decide it.
