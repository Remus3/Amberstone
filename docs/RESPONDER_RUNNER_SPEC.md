## 0. Status

SPEC, synthesized 2026-09-07 evening from three adjudicated designs and REPAIRED the same evening against 42 standing refutations (three passes: enforcement-gap, untrusted-bytes, measurement-integrity), then REPAIRED AGAIN the same night against an independent verifier's 16-item FAIL list (dollar cap removed from argv and config; attempt cap re-shaped from a retirement into a HOLD; per-cycle kill allowance so the section 11 sum is a bound; one export signature; `log_root`; value-taking flags; the real-spawn rule; CLI pinned at 2.1.251), then a THIRD pass against a second verifier's 9 cross-reference contradictions plus 8 should-fix items (one `prelude_row` shape; `envelope` as gate 9b; the LATENCY-ONLY path through the gate 12 tail; `runner-failed / attempt-cap` for the spawner-not-called tick; `parent_env` and a pre-resolved `claude_exe` in the contract; `surrogatepass` at both encode sites; runner-side (A) needles for runner constants). Nothing here exists yet; nothing here is production code. It exists so the next session can build the runner and satisfy RC's three pre-committed conditions to RSC without re-deciding: (1) a runner exists and CALLS `validate_proposal` with cycle-driving arms; (2) the spawn is read-only and a dry cycle has run end to end on a stub; (3) the invocation log records the cycles that did NOTHING. Settled items (A1-A5 as coded, disposition (i), M6 at zero, no stop rule, deterministic executor, arrival ordering, exhausted-vs-refused, LATENCY-ONLY as a distinct grammar) are inherited verbatim.

Two principles the repair added, each DECIDED and each with arms in section 12:
- PUBLIC-PROJECTION PRINCIPLE: every byte the spawned session can read and every byte a measure can print must be a projection of bytes already reachable from `origin/main` (the repo is public since 2026-09-07, so that set is already public). The checkout itself is NOT such a set: measured this evening, `git check-ignore` confirms `API-Key-Claude.txt`, `.mcp.json`, `ops/moon_sync_repos.json`, `config/operator_identity.json` are gitignored and present, `moon_sync_inbox/` holds over a hundred other parties' notes, and `git rev-list --count --reflog ^HEAD ^origin/main` returns 5182 commits reachable only via the reflog. So the spawn cwd is a tracked-only EXPORT of `origin/main` (section 3) and every revision a measure names must be an ancestor of `origin/main` (section 5).
- ONE-FUNNEL PRINCIPLE: every cycle of `run_once` leaves exactly one START line, one END line and one metrics row with the same `cycle_id`, written by one tagged `_finish` call site (the funnel census counts `_finish(` inside `def run_once` only), including cycles that raise inside a gate; a prelude failure in `main` before `run_once` leaves the same triple through `main`'s own fixed-shape writer `prelude_row` (section 9) - never through `_finish`, which `main` does not call, and never through `fallback_row`, whose `metrics-invalid` detail and `row_replaced` state mean nothing for a cycle that never started (sections 2, 8, 9, 12).

Untrusted byte flow the build is organised around: note FILENAME (disk) -> `pending_notes` -> `safe_name` projection for every sink reached before the name grammar -> `NOTE_NAME_RE` full-match -> stdin header + answered record + log field, NEVER argv, never a filename component. ONE NAMED EXCEPTION, the raw-name sink: a gate-6 (note-shape) refusal answers the note through `record_responded(root, name)` with the RAW failing name (inbox_responder.py:161-172), because `pending_notes` filters on `p.name in answered` (:194) and a projected name would never match, so the note would re-cycle every tick. That sink is ASCII-safe on disk ONLY because `json.dumps` defaults to `ensure_ascii=True` (a lone surrogate `\udcff` is written as the six ASCII bytes `\udcff`, and a non-ASCII byte as `\uXXXX`); the dependency is stated in section 6 and pinned by the note-shape arm's round-trip case (section 12). Note BODY -> lstat/fstat link checks -> nonce-fenced stdin bytes, never argv, never a path. Model `structured_output` -> `validate_proposal` -> executor hardening + public-revision pre-check on every positional -> list exec -> byte-level scrub -> assembled body -> output filter. `Decision.reason` is model-tainted and is scrubbed before it enters any row or body. Destination -> `participants[code]` where `code` passed two allowlists and the inbox dir resolved to itself. Reply filename -> 100 percent runner-authored. Cycle id -> clock + pid + urandom, never a sender byte.

## 2. run_once contract

```
def run_once(*, cycle_id: str, root: Path, repo_root: Path, inbox: Path, participants: dict[str, Path],
             spawner: Spawner, parent_env: Mapping[str, str], now: Callable[[], datetime],
             measure_runner=default_measure_runner, export=ensure_export, slot_root: Path | None,
             config: RunnerConfig, dry: bool = False, log_root: Path | None = None) -> CycleResult
```
DECIDED: `root` is the STATE root (every `ops/runtime/*` file, the answered record via `responder_state_path(root)`, held, outbox, agreement, deliveries, the attempts file `ops/runtime/inbox_responder_attempts.json`, export cache all derive from it); `log_root` (default `root`) is where `log_start` writes the START line and `_finish` writes the END line and the metrics row - ONLY those three writes; `main --dry-cycle` and the flag-file dry path pass the LIVE root as `log_root` while every other write goes under the scratch root (section 13), and the TEST of the dry path passes `log_root=tmp_path/"live"`; `repo_root` is the git tree used for A1 measures (git needs `.git`) and as the SOURCE of the tracked-only export that becomes the spawn cwd (section 3). Reason: the dry cycle must read the real tree while every write lands in scratch, and the dry row must still be task-fired evidence in the live log. Nothing inside `run_once` reads `__file__`, `os.environ` or `PATH`: `log_root`, `parent_env` (the mapping `child_env` pops the key from and the measure env is built over) and the pre-resolved `config.claude_exe` / `config.spawn_exe_source` / `config.git_exe` all arrive as arguments, and `main` is what resolves them - `parent_env = dict(os.environ)` captured once, `git_exe` via `shutil.which("git", path=parent_env.get("PATH"))`, the exe pair via `resolve_claude_exe(config, parent_env)` (sections 3, 9); the world fixture passes `parent_env` explicitly, so an arm that asserts the child env lacks `ANTHROPIC_API_KEY` never touches the process environment. `cycle_id` is REQUIRED and minted by the caller with `new_cycle_id(now)` = `f"{now():%Y%m%dT%H%M%S}-{os.getpid()}-{os.urandom(3).hex()}"`, matching `^\d{8}T\d{6}-\d+-[0-9a-f]{6}$`; it is the only path component under held/outbox/export and the START/END/row join key, and no sender byte can reach it (arm `cycle-id`).

DECIDED (one funnel): `run_once` computes a `CycleResult` and returns ONLY through `_finish(result)` (`# GATE:finish`, one call site; the funnel census counts `_finish(` inside `def run_once` only - the test slices the runner source from `def run_once` to the next top-level `def` - so `main`'s `prelude_row(` writer does not count against it and `main` never calls `_finish`), inside `try/finally` opened immediately after `log_start`; an exception anywhere after START yields `runner-failed / exception:<gate-tag>:<cls>` with an END line and a row. `_finish` writes the END line, then `metrics_row_ok(row)`; a failing row is held as `held/<cycle_id>/bad_row.json` and replaced by `fallback_row(result)` (section 8) so no cycle can end with a line and no row.

DECIDED: `runner-failed` is a ninth row-level value. Reason: an IO fault or runner bug filed under `refused` is RSC's reassuring-label bug wearing a gate's name; `spawn-failed` would misattribute it to the CLI. It is declared in the arming note (section 16). `overlap` and `mutex-unavailable` are `main`-level: they write a START and an END (`phase: "end"` like every END line, `termination` `overlap` / `mutex-unavailable`) and no row, exit 3 - they are not cycles of `run_once` (section 9). A START without an END of the same cycle_id is the ETL-kill detector; an END without a START is corruption, never expected.

DECIDED (slot-timeout and export do NOT count as spawn attempts): a slot timeout is local contention (`max_concurrent_lanes` 3, ops/loop/config.json:7; three-way contention never measured) and an export failure is a local git fault; neither says anything about the CLI, so both are `runner-failed` details (never `spawn-failed`), and three busy ticks must not hold a sibling's note against its attempt cap. Both leave the note pending. Arm `slot-no-attempt`: three slot-timeout cycles then a free slot -> the fourth cycle spawns.

DECIDED (attempt cap is a HOLD, never a retirement - repaired): `MAX_SPAWN_ATTEMPTS = 3` bounds AUTOMATIC spawns per note, keyed by `note_sha12` in `ops/runtime/inbox_responder_attempts.json` under `root`; it never bounds the conversation. The spawn that fails at the cap writes `held/<cycle_id>/status.txt` with reason `attempt-cap` (plus `spawn.json`), terminates `spawn-failed / <detail>:attempt-cap`, and does NOT call `record_responded`: the note stays pending and UNANSWERED in the record. From the next tick, gate 4b picks the oldest pending note still below the cap (a younger eligible note is answered; the capped one waits for the operator, not for a timer); when every pending note is at the cap the cycle terminates `runner-failed / attempt-cap` (the spawner is not called, so the CLI is not the cause) with `notes_at_cap` in the row - on EVERY tick, so the condition is loud, retires nothing, marks nothing answered, and resumes the moment the operator deletes the note's entry from the attempts file.
