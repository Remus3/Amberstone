## New findings

### HIGH

**H-01 — `broadcast_push` is sequential; one slow /push client blocks fanout**
- **File:line:** `agents/agent2_backend/ws_server.py:100-108`
- **What's wrong:** The fanout loop does `await ws.send(msg)` per client in
  series, inside a `for ws in list(self._push_clients):`. A laggy iPad or
  forwarder WS adds its full round-trip latency to every other subscriber
  waiting behind it. `except (ConnectionClosed, RuntimeError)` catches dead
  sockets but *not* slow ones; there is no timeout.
- **Why:** Violates the `right_now` 1-2s latency tier in
  `resolved_decisions.json`. Worst case: 3 subscribers, one idle/suspended,
  heartbeat fan-out stalls long enough that `HEARTBEAT_INTERVAL_SEC` (5s)
  is missed, push clients self-disconnect, UI reconnect storm.
- **Fix:**
  ```python
  async def _send_one(ws, msg, timeout=2.0):
      try:
          await asyncio.wait_for(ws.send(msg), timeout=timeout)
          return None
      except (websockets.ConnectionClosed, RuntimeError, asyncio.TimeoutError):
          return ws
  results = await asyncio.gather(
      *(_send_one(ws, msg) for ws in list(self._push_clients)),
      return_exceptions=False,
  )
  for dead_ws in filter(None, results):
      self._push_clients.discard(dead_ws)
  ```
- **Action:** Proposal `P-audit3-h01-ws-fanout-parallel` filed to Agent 1 queue for Agent 2.

**H-02 — `_heartbeat_loop` swallows only `CancelledError`; any other raise kills the heartbeat silently**
- **File:line:** `agents/agent2_backend/ws_server.py:163-169`
- **What's wrong:** If `broadcast_push` ever raises a non-`CancelledError`
  (e.g. a future size-validation raise, or `json.dumps` on a non-serialisable
  payload passed from the dispatcher), the heartbeat task terminates. The
  push log records nothing beyond the traceback line. Push clients see
  silence for 5s → disconnect → reconnect. The supervisor has no signal that
  heartbeats stopped.
- **Why:** Cascading UI flake that looks like "network wobble" but is a
  server-side dead task. Particularly bad post-H-01 fix (which will propagate
  exceptions upward).
- **Fix:** Wrap the inner `broadcast_push` in `try/except Exception as e:
  self._push_log.exception("heartbeat fanout failed: %s", e)` — keep the
  loop alive. Let `CancelledError` propagate as today.
- **Action:** Proposal `P-audit3-h02-heartbeat-guard` filed.

**H-03 — Safeguard invariant #8 (`resolved_decisions.json` version check) still not enforced at supervisor start**
- **File:line:** `agents/agent6_auditor/safeguards/startup_checks.md:18` claims NO;
  `agents/supervisor.py` — no call site.
- **What's wrong:** The decisions file is the phase-3 source of truth
  (`version: "phase3-1.1"`). Code that drifts from it is defined as a
  finding. Nothing currently fails closed on a version mismatch — an
  accidentally-downgraded or hand-edited decisions file boots cleanly.
- **Why:** Drift detection for the whole Phase 3 contract hinges on this.

- **Fix:** Add `EXPECTED_DECISIONS_VERSION = "phase3-1.1"` constant in
  `supervisor.py`; call a `_verify_decisions_version()` helper in
  `Supervisor.start()` that reads `agents/state/resolved_decisions.json`
  and raises `RuntimeError` if `version` differs. Keep the message loud
  enough that a human sees it in the supervisor log.
- **Action:** Safeguards doc updated autonomously (this pass); code change
  filed as proposal `P-audit3-h03-decisions-version-check` (touches
  `supervisor.py` which is not frozen but is load-bearing — prefer queue).

### MEDIUM

**M-01 — Ephemeral-LLM spawn proceeds with empty charter, only WARNs**
- **File:line:** `agents/supervisor.py:442-472`
- **What's wrong:** If `charter_path` doesn't exist or fails to read, the
  `claude` CLI is invoked without `--append-system-prompt`. The spawn still
  burns budget (`--max-budget-usd`) and returns a JSON envelope, but the
  agent has no role identity and will act generically. User only sees the
  warning in `logs/agents/supervisor.log`.
- **Why:** Agent 4 / Agent 5 / Agent 6 each depend on their charter for
  scope-of-authority. An empty-charter spawn silently widens authority
  (no "you may only propose-and-queue" constraint). Budget is charged for
  output that's not useful.
- **Fix:** If `charter_path` is declared in `AGENT_CHARTERS` and the file is
  missing or empty, raise `EphemeralStubNotWired(...)` so the dispatcher
  routes to `Scheduler.fail()` (same pattern as H3 from first audit).
  Cost: the `log.warning` branch becomes a `raise`.
- **Action:** Proposal `P-audit3-m01-charter-fail-loud` filed.

**M-02 — DDragon cache-read paths have no `JSONDecodeError` handling**
- **File:line:** `lib/ddragon/fetch.py:82, 88, 94, 100` (and similar sibling
  reads).
- **What's wrong:** `json.loads(p.read_text(encoding="utf-8"))` — no try.
  A corrupted cache file (partial write interrupted mid-process, disk
  corruption, user edit) propagates `JSONDecodeError` to the caller.
  Coaches calling `ddragon.items()` or `ddragon.champions()` crash on
  first use after a bad file appears.
- **Why:** DDragon is a hot read path for every coach. `_atomic_write_json`
  already protects writers — readers are the hole.
- **Fix:** Wrap each cache read in `try/except (JSONDecodeError, OSError):
  log.warning(...); return self._pull(name)`. Stale-while-revalidate by
  re-fetching on corruption.
- **Action:** Proposal `P-audit3-m02-ddragon-cache-parse-guard` filed.

**M-03 — Test suite hardcodes Python 3.14 absolute path**
- **File:line:** `agents/agent3_testing/suite/test_supervisor.py:16`,
  `test_scheduler_lock.py:18`
- **What's wrong:** `PY = r"C:\Users\Administrator\AppData\Local\Programs\Python\Python314\python.exe"`.
  Any future machine, container, or user account diverges from this path and
  the tests either skip silently (if `if not Path(PY).exists(): pytest.skip`)
  or fail with an un-obvious "file not found".
- **Why:** Reproducibility. Next Python upgrade (3.15) silently breaks CI.
- **Fix:** `PY = os.environ.get("RC_PYTHON") or sys.executable`. Keeps the
  env-var override for deliberately testing a specific interpreter.
- **Action:** Proposal `P-audit3-m03-test-python-path` filed.

**M-04 — Scheduler silently drops corrupted lines from `task_queue.jsonl` on load**
- **File:line:** `agents/agent1_lead/scheduler.py` — per-line parse in `_load`
  (invariant #7 in `safeguards/startup_checks.md:17` marks this "Partial —
  bad lines silently dropped").
- **What's wrong:** If a partial write ever corrupts a queue entry, the
  restart-path task is lost with no signal. `acquire_lock`/atomic writes
  make this unlikely but not impossible (e.g., disk-full mid-append).
- **Why:** Silently eaten work is worse than a loud crash — Agent 1's
  scheduler is the queue of record.
- **Fix:** On `json.JSONDecodeError` at load time, emit `log.error` with the
  line number and the first 120 chars; continue loading. Don't stall, but
  make it visible. Optionally file an `audit-queue-corruption` task to
  Agent 6.
- **Action:** Proposal `P-audit3-m04-queue-load-error-log` filed.
