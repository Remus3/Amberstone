- Location: `agents/state/resolved_decisions.json` line 89 (id `phase3-d008`)
- What: The `Topology - Legion + Game-PC + Peer tailnet` decision summary
  still reads "Game-PC (gamepc-rc / 100.95.66.128 / LAN 192.168.8.237) runs
  League + Chrome on secondary monitor" as if it were a live peer.
- Why wrong: ADR-011 (d011, 2026-05-29) retired Game-PC from the pipeline
  and consolidated to 1-PC Legion; ADR-012 (d012, 2026-06-24) decommissioned
  the RC<->Peer bridge. Charter line 16 forbids cross-machine writes.
  The truth-source-of-record contradicts the two ADRs that supersede it.
- Fix (diff sketch):
  ```
  - "summary": "Legion (legion-rc / ...) runs RC + supervisor + vision server + web dashboard. Game-PC (gamepc-rc / ...) runs League + Chrome on secondary monitor (panel 1920x1280 native at 100% scale). Peer (peer-host / <peer-tailnet-ip>) is cross-Claude peer for RC<->Peer bridge. All three in tailnet ..."

Both remaining nodes in tailnet tailc150de.ts.net. Vision runs in-process at 127.0.0.1:8889."
  ```
- Disposition: **proposal filed** (see follow-up P-1 below).

### F-3 - Evaluator accepts trailing-empty-segment path
- Severity: **low**
- Location: gatekeeper safeguard (`agents/agent0_gatekeeper/evaluator.py`,
  via probe in `agents/agent6_auditor/_audit_probes.py:16`)
- What: `\\192.168.8.237\RCClient\web\\` passes the traversal + subdir +
  payload checks (accepted=True). The empty trailing segment isn't treated
  as a malformed leaf.
- Why wrong: Any downstream `os.path.join`/`smb_push` that consumes an
  empty-leaf path can silently write to a directory instead of a file.
- Why not higher: d020 established that the SMB pipeline is dead
  (share_reachable is hard-False, push raises RuntimeError), so the
  guard is a defense-in-depth net for a target that no longer exists.
  Charter says the guard is KEPT as a standing safety net - so tightening
  it is still worthwhile, just not urgent.
- Fix (pseudo): reject any path whose final `PurePath(p).name` is empty
  string, alongside the existing traversal check.
- Disposition: **info only this pass**; not filed as a task. Log entry
  here documents the accept-True outcome for the next auditor.

### F-4 - `game-summary` task retries flood the queue with "missing champion"
- Severity: **medium**
- Location: `agents/state/task_queue.jsonl` (79 entries observed)
- What: Between 2026-04-26 and 2026-07-26 the queue captured 79 completed
  `game-summary` dispatches, all with `payload.champion == "Unknown"` and
  `result.inserted=False result.reason="missing champion"`. Every one
  landed via `game_ingest.ingest_game_summary` and correctly refused the
  insert. Nothing on the emit side backs off or dedupes.
- Why wrong ("bad process", auditor scope): the emitting handler (Agent 2
  game-lifecycle) has no gate on `champion == "Unknown"`. Every stale
  coaching_data.json read re-files a task that the handler is guaranteed
  to reject. The queue is a growing pile of no-ops.
- Fix (pseudo): in the game-summary emitter, drop-and-log rather than
  enqueue when `champion in {"", "Unknown", None}`. Keep the ingest-side
  refusal as belt-and-braces.
- Disposition: **proposal filed** (see P-2 below). Belongs to Agent 2
  (backend/game-lifecycle emitter), not agent6 autonomous scope.
