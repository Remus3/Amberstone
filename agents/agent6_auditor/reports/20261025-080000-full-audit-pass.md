## F1 - high - task_queue.jsonl cross-process lock does not exclude
- Location: agents/agent1_lead/scheduler.py:234 (_lock_file_exclusive), :278 (_append_log opens "a"), :305 (compact opens "r+").
- What: msvcrt.locking locks one byte at the CURRENT position. Append handles sit at EOF, the compactor at 0, so they lock different bytes. Measured 2026-10-25: "a" handle locked offset 100, an "r+" handle then acquired LK_NBLCK at offset 0 -> no exclusion. After 5 s contention the helper also "proceeds unlocked", including for compact()'s truncate.
- Why: separate processes / separate Scheduler instances write the queue (agents/supervisor.py:328, agents/agent7_context/input_parser.py:118, ui_feedback.py:106, ops/phase3_file_audit.py:90, scheduler __main__). compact() reads, truncates and rewrites in place, so a concurrent append can be lost or interleaved; a crash mid-rewrite loses the queue (not tmp -> os.replace).
- Fix: seek(0) before lock and unlock in both paths (restore position; O_APPEND still writes at EOF), or lock a sidecar task_queue.jsonl.lock at offset 0; compact() must skip when the lock is not acquired. Diff sketch in proposal.
- Disposition: proposal agents/agent6_auditor/proposals/20261025-080000-h01-queue-lock-offset/, task t-58a7b703e0b6 (Agent 2).
