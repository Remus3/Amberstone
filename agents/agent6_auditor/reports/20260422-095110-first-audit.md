## High

### H1 — Evaluator accepts path-traversal (`..`) segments
`[P-audit-h1]`

- **Location:** `agents/agent0_gatekeeper/evaluator.py:122-124` (`_destination_prefix_ok`)
- **Probe:** `_audit_probes.py` case "traversal escape" — the path
  `\\192.168.8.237\RCClient\web\..\..\x.html` is **accepted** because the
  prefix `\\192.168.8.237\RCClient\web\` matches and `.html` is an allowed
  extension. Only `smb_push.push()`'s `resolve().relative_to()` check at
  `agents/agent2_backend/smb_push.py:121-124` catches it.
- **Risk:** Agent 0 is supposed to be a defense layer above `smb_push`. Any
  future code path that writes to the share without going through
  `smb_push` — plausible, given multiple agents with push authority —
  bypasses the only line of defense against traversal.
- **Fix:** add a `_has_traversal(path)` helper that rejects any segment
  equal to `..` (or URL-encoded `%2e%2e`), invoked at the top of
  `evaluate()` as REASON_DESTINATION:

  ```python
  def _has_traversal(self, path: str) -> bool:
      # Split on both / and \ to catch mixed separators.
      parts = path.replace("/", "\\").lower().split("\\")
      return ".." in parts or "%2e%2e" in parts
  ```

- **Why not autonomous:** modifies core evaluator logic. Per charter,
  code changes are propose-and-queue.

### H2 — No process-level lock on `task_queue.jsonl`
`[P-audit-h2]`

- **Location:** `agents/agent1_lead/scheduler.py:108-116` (`_append_log`)
- **What:** The scheduler holds a `threading.RLock` but nothing prevents
  a second Python process from also opening and appending. `ops.phase3_queue_first_audit`
  already demonstrates this: it instantiates a second Scheduler against
  the same log while the supervisor's Scheduler may also be live.
- **Risk:** concurrent appends corrupt ordering; reload-replay on startup
  may reconstruct inconsistent state. On Windows, append is not atomic at
  the OS level when writes cross sector boundaries (~512 B). Our records
  average ~400-1200 B — possible.
- **Fix:** `msvcrt.locking(f.fileno(), msvcrt.LK_LOCK, ...)` at append
  time, or a sidecar `.lock` file checked against a pid. The simplest
  robust fix is a file-level `LK_NBLCK` with a short retry on failure.
- **Why not autonomous:** charter change; need a supervisor-lifecycle aware
  lock.

### H3 — `spawn_ephemeral_llm` reports success on every call
`[P-audit-h3]`

- **Location:** `agents/supervisor.py:190-205`
- **What:** Stub returns `{"dispatched": True, ...}` regardless of whether
  real work happened. The scheduler then calls `complete(task_id, result=...)`,
  marking the task COMPLETED in the JSONL log.
- **Risk:** until real subprocess spawning lands, every enqueued
  LLM-agent task gets **falsely marked complete**. A human looking at
  the queue has no way to tell real completions from stub dispatches.
  This silently inflates "done" status and breaks the `blocks_all_subsequent`
  semantics of the first audit task — the audit would appear complete
  with no work done.
- **Fix:** until the real spawn is wired, the stub should return
  `{"dispatched": True, "substrate": "stub_no_op", "note": "charter not yet wired"}`
  and the supervisor should call `scheduler.fail(task_id, "stub_no_op — not real work")`
  instead of `complete()`. That way the task stays visible as failed, not
  silently green.
- **Why not autonomous:** changes supervisor dispatch logic.

## Medium

### M1 — Backup path in `smb_push` has no test coverage
`[P-audit-m1]`

- **Location:** `agents/agent3_testing/suite/test_smb_push.py`
- `test_push_web_roundtrip` writes once; `_backup_existing` returns None
  (no prior file). The backup branch is never exercised.
- **Fix:** extend to push the same filename twice and assert `result["backup"]`
  is non-None on the second write + the backup file matches the first payload.

### M2 — Migration silently corrupts comp split when `tracked_team_id` is null
- **Location:** `agents/agent2_backend/migration_rewind.py:238`
- `tracked_team_id or 100` defaults to blue side when null. If the tracked
  player was actually on red team in a given historic row, all 10 participants
  end up classified as enemies (or allies).
- **Fix:** skip the match entirely if `tracked_team_id` is null — tag the
  skip with a DEBUG log line.
- **Filing:** `[P-audit-m2]`

### M3 — Subdir match uses substring, not prefix
- **Location:** `agents/agent0_gatekeeper/evaluator.py:139`
- `f"\\rcclient\\{sub}\\" in rp` uses `in` — reads any position. Combined
  with the `..` traversal gap (H1), paths like
  `\\192.168.8.237\RCClient\forwarder\..\RCClient\web\x.html` can pass
  unintended subdir checks. With H1 fixed, this is defused; listing
  separately because it's a latent sharp edge.
- **Fix:** require the subdir to immediately follow the share root.
- **Filing:** rolled into H1 proposal `[P-audit-h1]`.

### M4 — Scheduler silently blocks on unknown `blocked_by` ids
- **Location:** `agents/agent1_lead/scheduler.py:220-225` (`_blocked`)
- If a `blocked_by` id references a task that was never filed, `_blocked`
  returns True forever. The task sits in READY but can never dispatch.
- **Fix:** during `file_task`, validate that all `blocked_by` ids exist;
  log a WARNING and drop unknown ids.
- **Filing:** `[P-audit-m4]`

### M5 — `websockets.serve` uses default `max_size=2**20` (1 MB)
- **Location:** `agents/agent2_backend/ws_server.py:163`
- Current topology routes screenshots through a separate HTTP path
  (`:8889/upload-frame`), so the 1 MB cap is fine. If Phase 3 ever moves
  screenshot streaming onto the WS, frames will be rejected silently.
- **Fix:** set an explicit `max_size=2**20` (or `None` if screenshots
  ever land here) in `serve()` to make the policy visible.
- **Filing:** `[P-audit-m5]`

## Low

### L1 — `acquire_lock` is non-atomic across concurrent starts
- Two simultaneous starts can both pass the `pid_alive` check before
  either writes. Classic TOCTOU. For Task-Scheduler-driven boot this is
  unreachable in practice; during manual testing a simple
  `os.open(..., O_CREAT|O_EXCL)` on a sentinel file would remove the
  ambiguity.

### L2 — No early port-conflict check
- `supervisor.start` lets `socket.bind` raise if 8890/8891 are already
  bound. Error surfaces but the message is opaque. Pre-flight probe +
  friendly log line would help.

### L3 — SMB `label` parameter is not sanitised
- Labels flow into `backup/<ts>-<label>/` directory names. A label
  containing `:` or `\` could fail on Windows. Callers today pass known
  literals, so no live risk; a `label = re.sub(r"[^A-Za-z0-9._-]", "-", label)`
  guard costs nothing.

### L4 — `http.server.SimpleHTTPRequestHandler` has no auth, no content-type
  pinning
- Handler serves anything under `web/`. The firewall rule scopes
  exposure to LAN, and `web/` is intended to be public anyway. If a
  developer ever drops a `.env` or `secrets.json` in `web/`, it would be
  served without distinction. A future safeguard: deny-list filenames
  and dotfiles at the handler level.
