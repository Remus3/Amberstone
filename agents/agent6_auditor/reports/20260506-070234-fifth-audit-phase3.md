## New findings

### HIGH

**H-01 - `_warm_agent7_alive` referenced but never initialized; queue-dispatched Agent 7 tasks AttributeError on every call**
- **File:line:** `agents/supervisor.py:1812` (`if not self._warm_agent7_alive:`),
  init block at `:1535-1558` does not set the attribute. Compare to
  sibling `self._warm_agent7: WarmAgent7Session | None = None` at
  `:1542` which *is* initialized.
- **What's wrong:** The dispatch loop at `:1735-1736` routes every
  `owner_agent == "7"` queue task to `_warm_agent7_handle`. The first
  line of that handler reads `self._warm_agent7_alive`, which has no
  prior assignment anywhere in the class - Python raises
  `AttributeError` before reaching the `if`. The exception is caught
  by the generic `except Exception` at `:1740-1742` and flipped to a
  `scheduler.fail()`, so the symptom is "Agent 7 queue tasks fail with
  `'Supervisor' object has no attribute '_warm_agent7_alive'`."
- **Why it matters:** Any op the InputParser routes through the queue
  for owner_agent=7 (vs. the inline `/api/input` path which bypasses
  the queue via `warm_spawn_factory` at `:493`) will fail every time.
  Today the inline `/api/input` path is the dominant flow, so the bug
  is latent - but any future op that files a `7`-owned task (or
  anything currently filed at low frequency) fails permanently.
- **Concrete fix:** Add `self._warm_agent7_alive: bool = False` to the
  `__init__` block alongside line 1542.
- **Action:** Proposal `P-audit5-h01-warm-agent7-alive-init` filed for
  Agent 2 (proposals dir created since previous audits had none).

**H-02 - `_warm_agent7_handle()` does not use the warm session; falls through to ephemeral spawn, defeating Phase 3 latency/cost guarantee**
- **File:line:** `agents/supervisor.py:1811-1815`. Compare to
  `:489-501` where the inline `/api/input` path correctly wraps
  `warm_spawn_factory(warm)` with an ephemeral fallback.
- **What's wrong:** The handler logs "warming agent7 session", flips
  the (uninitialized - see H-01) `_warm_agent7_alive` flag, then
  unconditionally returns `spawn_ephemeral_llm("7", task.id, ...)`.
  `self._warm_agent7` is never consulted on this path. The warm
  instance is created at `:1599`, primed on game-start (`:1842`) and
  champ-select (`:1859`), but for queue-dispatched Agent 7 work the
  warm context is silently bypassed - every queue task pays full cold
  subprocess startup (≈5 s) and full input-token cost.
- **Why it matters:** Charter pledges "warm-session substrate for
  Agent 7" with ~6× cost reduction and sub-second latency. Inline
  `/api/input` honors this; queue dispatch does not. As soon as any
  background op on Agent 7 starts riding the queue (e.g. a future
  scheduled summary, a deferred parse), it pays the full cold price
  and the warm session sits idle.
- **Concrete fix:** Mirror the inline pattern from `:494-500`:
  ```python
  def _warm_agent7_handle(self, task) -> dict:
      if self._warm_agent7 is None:
          return spawn_ephemeral_llm("7", task.id, task.op, task.payload)
      try:
          msg = task.payload.get("message") or task.payload.get("user_text") or ""
          if not msg:
              return spawn_ephemeral_llm("7", task.id, task.op, task.payload)
          reply = self._warm_agent7.send(
              msg, max_tokens=int(task.payload.get("max_tokens", DEFAULT_MAX_OUTPUT_TOKENS)),
          )
          return {
              "ok": True, "substrate": "warm_agent7_session",
              "model": reply["model"], "exit_code": 0, "elapsed_sec": 0.0,
              "result": {"type": "result", "subtype": "success",
                         "result": reply["text"],
                         "usage": {"input_tokens": reply["input_tokens"],
                                   "output_tokens": reply["output_tokens"]}},
          }
      except WarmSessionError as e:
          log.warning("warm send failed, falling back to ephemeral: %s", e)
          return spawn_ephemeral_llm("7", task.id, task.op, task.payload)
  ```
  Or, more simply: reuse `warm_spawn_factory(self._warm_agent7)` and
  delegate. Either way, fold in the H-01 fix so the dead-code
  `_warm_agent7_alive` flag either becomes a real liveness gauge or
  is removed.
- **Action:** Proposal `P-audit5-h02-warm-agent7-actually-warm` filed
  for Agent 2. Bundle with H-01.

### MEDIUM

**M-01 - `WarmAgent7Session.stats()` reads `_client` and `_last_activity` outside the lock; watchdog can observe inconsistent state**
- **File:line:** `agents/agent7_context/warm_session.py:194-207`
  (`stats()` body - no `with self._lock:`). Mutators
  (`close()` `:127-131`, `send()` `:148-191`, `_check_idle()`
  `:113-124`) all hold `_lock`. Reader `stats()` does not.
- **What's wrong:** Two race windows:
  1. `close()` clears `_messages`, sets `_client=None`, sets
     `_last_activity=0.0` (in that order, all under `_lock`). A
     concurrent `stats()` that runs between the second and third
     statement returns `{"warm": False, ..., "idle_sec": <large
     positive>}` - but if it runs between first and second, it
     returns `{"warm": True, ..., "idle_sec": <large positive>}`,
     which contradicts `warm=True`'s normal invariant
     (`_last_activity > 0`).
  2. `_warm_ui_watchdog` (`agents/supervisor.py:1683-1702`) polls
     `stats()` to decide when to call `close()`. If the watchdog
     observes a stale `warm=True` shortly after a `close()` from
     elsewhere, the next poll may miss the transition entirely and
     leave it believing the session is hot.
- **Why it matters:** Symptoms are subtle (occasional missed
  warm-prime on game-start, an extra `close()` log line) rather than
  user-visible bugs. But the dashboard `/api/agent7/stats`
  endpoint (`:2154-2155` exposes `warm_agent7`) feeds straight to
  UI - stale flags there mislead the operator about whether the
  session is hot.
- **Concrete fix:** Wrap the `stats()` body in `with self._lock:`.
  All reads are O(1) and the lock is uncontended unless `send()` is
  mid-flight, which is the same window where the watchdog wants
  consistent state anyway.
- **Action:** Proposal `P-audit5-m01-warm-stats-lock` filed for
  Agent 2.
